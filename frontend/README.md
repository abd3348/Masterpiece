# Campus Mate — واجهات فقط

افتح `index.html` مباشرة في المتصفح. لا تحتاج إلى تثبيت مكتبات أو تشغيل سيرفر.

المشروع مبني بـ HTML وCSS وJavaScript، مع بيانات JSON وطبقة API جاهزة للربط لاحقًا مع ASP.NET Core. الوضع الافتراضي تجريبي، بدون باك إند أو LocalStorage أو SessionStorage. تغييرات التجربة مؤقتة وتختفي عند تحديث الصفحة. في وضع API يستعيد التطبيق البيانات من السيرفر.

## JSON والربط مع ASP.NET

مصدر البيانات التجريبية هو `data/campus-seed.json`. عند التشغيل عبر HTTP يُقرأ مباشرة؛ عند فتح الملفات يستخدم التطبيق نسخة مولدة في `js/seed.js`. بعد تعديل JSON شغّل `node tools/build-seed.js` لتحديث نسخة الفتح المباشر.

إعدادات الربط في `js/config.js`. بعد بناء الباك إند عدّل `mode` إلى `api` وحدد `apiBaseUrl`. عقد المسارات والـ DTOs في `docs/openapi.json`، وأمثلة الطلبات والردود في `data/api-examples.json`. اتبع [دليل ASP.NET](docs/ASP_NET_INTEGRATION.md) قبل تفعيل الوضع الحقيقي.

## تجربة الأدوار

الدور مرتبط بالحساب الذي تسجل الدخول به. لا توجد قائمة لتبديل الدور من داخل الموقع، ولا يتحول الحساب تلقائيًا عند فتح صفحة المالك أو الإدارة. للتنقل بين الحسابات، سجّل الخروج ثم ادخل بالحساب الآخر. يتضمن ملف JSON ثلاثة مستخدمين أساسيين فقط: مستأجر ومالك وأدمن.

يمكن أيضًا تسجيل الدخول بالحسابات التجريبية التالية. كلمة المرور لجميعها: `Campus123`.

| الدور | البريد |
| --- | --- |
| مستأجر | tenant@campus.test |
| مالك | owner@campus.test |
| إدارة | admin@campus.test |

الحسابات الجديدة تعمل في الجلسة الحالية فقط. لا توجد مصادقة أو عملية دفع حقيقية.

## نموذج العمل

يدفع المالك **20 دينارًا لكل إعلان عقار جديد** قبل نشره. تعديل الإعلان المدفوع لا يفرض رسوم نشر إضافية. الإعلان الجديد يبقى `awaiting-fee` حتى تأكيد رسومه، ثم ينشر أو ينتظر مراجعة الإدارة حسب فحصه. رسوم النشر لا تضمن التأجير. لا توجد مدة انتهاء أو تجديد تلقائي مفروضة في هذه النسخة.

التصفح والتواصل مجانيان للمستأجر. الإيجار والتأمين والاتفاق والدفع مباشرة بين المالك والمستأجر؛ تعرض المنصة السعر المطلوب ولا تجمع أو تتحقق من دفعات الإيجار ولا تصدر إيصالات لها. خطوة «Confirm arrangement» تسجل اتفاق الطرفين فقط. رسوم الإعلان وحدها تحاكى في الوضع التجريبي؛ التحصيل الحقيقي يحتاج مزود دفع وباك إند يؤكد الدفع.

يختار المستأجر الزميل من صفحة Roommates باستخدام **Choose for rental**، أو يحدده مباشرة في نموذج طلب الإيجار. في الطلب يختار **I will rent alone** أو **I will rent with a roommate**؛ الخيار الثاني يتطلب اختيار شخص. يظهر اسم الزميل لصاحب الشقة وفي الاتفاقية، ولا تغيّر نسبة التوافق اختيار المستأجر. بيانات `roommates` هي ملفات أشخاص تجريبية للاختيار، وليست حسابات دخول إضافية داخل `users`.

لموافقة الطلب: أرسله بحساب المستأجر، ثم سجّل الخروج وادخل بحساب المالك وافتح الطلبات، ثم عد إلى حساب المستأجر لإكمال الاتفاقية. يبقى الطلب خلال التنقل بين الحسابات في الجلسة نفسها.

## لقاءات الفيديو

زر **Book a meeting** يظهر على ملف زميل السكن وصفحة العقار، ويمكن للمالك دعوة مستأجر من طلبه. يحدد المرسل العنوان والموعد بتوقيت الأردن والمدة (15 أو 30 أو 60 دقيقة). الدعوة تكون `pending` حتى يقبلها المستلم أو يرفضها. يمكن للطرفين إلغاء اللقاء، والقبول يمنع تعارض اللقاءات المؤكدة للمشاركين. زر **Refresh invitations** يجلب آخر الردود.

تظهر اللقاءات في قائمة **Meetings**. تبقى روابط `messages.html` القديمة فعالة وتفتح واجهة اللقاءات للتوافق مع الروابط السابقة. يفتح **Join meeting** قبل البداية بعشر دقائق وحتى نهاية المدة، بعد موافقة المستلم. تُفتح واجهة Jitsi عند الضغط على الانضمام فقط، ويُنهي زر المغادرة واجهة الفيديو. اللقاء لا يعني قبول طلب الإيجار أو دفع أي مبلغ.

ملفات زملاء السكن التجريبية ليست حسابات دخول؛ لذلك يوجد زر واضح لمحاكاة قبولها دون تغيير المستخدم المسجل. في التشغيل الحقيقي يجب ربط كل ملف زميل بحساب مستأجر وحفظ الدعوات والردود في الباك إند حتى تصل بين الأجهزة. يحتاج الفيديو اتصال إنترنت وصلاحيات الكاميرا والميكروفون، ويُفضّل تشغيل الموقع عبر HTTPS. مضيف اللقاء على `meet.jit.si` قد يحتاج تسجيل دخول لدى Jitsi. صلاحيات التطبيق تحمي صفحة الانضمام، لكن غرف خدمة Jitsi العامة ليست مصادقة بحساب Campus Mate؛ حصر دخول الغرفة نفسها في المشاركين يحتاج نشر Jitsi بمصادقة أو خدمة تدعم رموز دخول يتحقق منها المزود.

الصور المختارة حتى 10 MB، والفيديو حتى 100 MB. في وضع التجربة تُعايَن الملفات محليًا؛ في وضع API تُرفع إلى مسار `/media` على السيرفر الذي تحدده. الصور التجريبية والخطوط الخارجية تحتاج إلى الإنترنت؛ عند تعذر تحميل الصور تُستخدم رسومات محلية بديلة.

## Regular Expression

التحقق المركزي في `js/validation.js`، ويُطبق على الحقول باستخدام `data-regex` ورسائل `setCustomValidity`.

| القاعدة | مثال مقبول | مثال مرفوض |
| --- | --- | --- |
| الاسم العربي أو الإنجليزي | عبدالله أحمد / Jean-Luc | Sara123 |
| البريد | first.last+tag@uni.edu.jo | a..b@example.com |
| الهاتف الأردني | 0791234567 / +962791234567 | 0801234567 |
| كلمة المرور | TestingPass1 | testingpass1 |
| المبلغ | 190.50 | 1e3 |
| التاريخ | 2028-02-29 | 2027-02-29 |
| اسم ملف صورة | room.png | room.svg |
| اسم ملف فيديو | walkthrough.mp4 | video.exe |

تُفحص صحة التاريخ، النطاقات الرقمية، تأكيد كلمة المرور، نوع الملفات وحجمها بجانب Regex. لا يمكن لـ Regex وحده التأكد من هذه العلاقات.

## تعديل المشروع وفحصه

مصادر الصفحات مفصولة في `html/tenant/` للمستأجر، و`html/landlord/` لصاحب الشقة، و`html/admin/` للإدارة، و`html/auth/` للدخول، و`html/public/` للصفحات العامة. لكل دور مسارات وقائمة تنقل خاصة، وصفحات طلبات وحجوزات المالك مستقلة عن صفحات المستأجر.

لكل صفحة HTML ملف CSS وملف JavaScript بالاسم نفسه داخل مجلد الدور. ملفات JavaScript الخاصة بالصفحات موزعة على المجلدات نفسها داخل `js/`، والسلوك المشترك في `js/shared/`. تعريف المسارات في `js/routes.js`. انظر [دليل تنظيم المشروع](docs/PROJECT_STRUCTURE.md) و[جدول ملفات الصفحات](docs/PAGE_FILES.md) و[تفاصيل تنظيم الكود والتحقق](docs/REFACTORING.md).

التنسيقات في `css/`، و`css/shared/layout.css` يوحّد التنقل والهوامش والنماذج والتجاوب في جميع الصفحات. راجع [المشاكل التي تم إصلاحها وصور المقارنة](docs/DESIGN_REVIEW.md). بعد تعديل ملفات HTML، شغّل `node tools/build-pages.js` لإعادة توليد `js/pages.js`؛ الأداة تقرأ المجلدات الفرعية. القوالب تسمح بالتنقل بدون طلب صفحات من سيرفر وتحافظ على البيانات المؤقتة. تشغيل المشروع نفسه لا يحتاج إلى Node.

أدوات الفحص خاصة بالتطوير وليست جزءًا من التطبيق:

- `node --test tests/api.test.cjs tests/http.test.cjs tests/structure.test.cjs` — تحقق من Regex وتدفق الإيجار وAPI ومسارات الأدوار وروابط الصفحات والملفات.
- `node tests/browser-flow.cjs --file` — فحص واجهات الكمبيوتر والموبايل مباشرة من القرص، باستخدام Chrome أو Edge محلي.
- `node tests/browser-flow.cjs` — فحص التجربة مع تحميل JSON عبر HTTP.
- `node tests/browser-flow.cjs --api` — فحص طبقة API باستخدام سيرفر اختبار محلي وفق العقد.
- `node tests/design-audit.cjs --after` — مراجعة كل الصفحات وتبويبات الإدارة على أربع مقاسات، مع صور للتصميم وفحص القوائم والصور وأحجام عناصر التحكم.
- أضف `--capture` لفحص وضع التجربة لحفظ صور الواجهات في `tests/artifacts/`.
