## الفصل بين الأدوار

صفحة `tenant/requests.html` لمتابعة المستأجر لطلباته، بينما `landlord/requests.html` لمراجعة صاحب الشقة طلبات عقاراته. صفحة الحجوزات والمحادثات والملف الشخصي وتقارير الحالة لكل منهما لها مسار مستقل.

السلوك المتشابه، مثل إرسال الرسائل أو عرض تقرير الحالة، يستخدم ملف JavaScript مشتركًا من `js/shared/`. إدارة عقارات المالك ووظائف الإدارة لا تُحمّل مع صفحات المستأجر. بيانات JSON وطبقة API مشتركة لتبقى الطلبات نفسها ظاهرة للطرفين وفق دور الحساب.

تحدد `routes.js` المسارات الفعلية، وتحدد `access.js` القسم المتاح للحساب. فتح قسم دور آخر يُعيد المستخدم إلى لوحة حسابه، والزائر يُوجَّه إلى الدخول. لم يتغير عقد ASP.NET بسبب نقل صفحات HTML.

الروابط القديمة داخل عنوان التطبيق، مثل `#home.html` أو `#landlord.html?tab=requests`، تُحوَّل إلى المسارات الجديدة. ملفات HTML القديمة في جذر `html/` نُقلت إلى المجلدات الجديدة. فتح ملف HTML من أحد المجلدات مباشرة يعيد المستخدم إلى نقطة التشغيل الرئيسية.

## تعديل الصفحات

لكل صفحة ثلاثة ملفات بالاسم نفسه؛ مثل `html/tenant/request.html` و`css/tenant/request.css` و`js/tenant/request.js`. الهيكل الثابت في HTML، والتنسيق في CSS، والأحداث والمحتوى المعتمد على البيانات في JavaScript. انظر [جدول جميع ملفات الصفحات](PAGE_FILES.md).

ملفات CSS التي لا تحتاج قواعد خاصة تستورد `css/shared/flow.css`. هذا يحافظ على الثيم ويمنع تكرار القواعد، ويوفر مكانًا واضحًا لتنسيق الصفحة لاحقًا. ملف `css/shared/interior.css` هو أساس التصميم الداخلي السابق؛ أبقيناه مشتركًا للحفاظ على التصميم وترتيب الاستيراد.

صفحات الرسائل والملف وتقارير الحالة لها ملفات تشغيل صغيرة تستخدم السلوك المشترك من `js/shared/`. ملفات المالك التي تتشارك إدارة العقارات تستخدم `js/landlord/shared.js`. فصل ملفات التشغيل يجعل الصفحة واضحة دون نسخ المنطق المتشابه.

عدّل المصدر في مجلد الدور، ثم شغّل:

```text
node tools/build-pages.js
```

الأداة تقرأ المجلدات الفرعية تلقائيًا. عند إضافة صفحة جديدة، أضفها أيضًا إلى قائمة القسم داخل `js/routes.js`، ووصلها بملف السلوك المناسب. لا تعدّل `js/pages.js` يدويًا.

تحميل التنسيق: ملف الصفحة المطابق لاسمها، ثم `css/shared/campus-theme.css` للصفحات الداخلية، ثم `css/shared/features.css`، وأخيرًا `css/shared/layout.css`. ترتيب الملفات والقواعد مهم للحفاظ على نتائج CSS الحالية. كل صفحة تحمل `data-section` و`data-screen` لتطبيق تعديلات القسم والصفحة. تفاصيل الإصلاحات وصور المقارنة في [مراجعة التصميم](DESIGN_REVIEW.md)، ونتائج التنظيم في [مراجعة إعادة الهيكلة](REFACTORING.md).

## الانتقال لاحقًا إلى MVC

يمكن أولًا استضافة الملفات كما هي في `wwwroot` والربط بالعقد الموجود. عند تحويل الصفحات إلى Razor، تصبح ملفات HTML مصدرًا لـ Views، ويمكن نقل التنقل والتذييل والقالب الثابت للمساعد إلى Layout وPartials. تبقى ملفات CSS وJavaScript في `wwwroot` بحسب الدور والصفحة. لا يحتاج المشروع الحالي إلى Controllers أو Models أو تغيير نظام التنقل؛ هذه خطوات التحويل المستقبلي. تعريفات المسارات في `js/routes.js` وعقد JSON في `docs/openapi.json` يظلان كما هما.

الفحوص:

```text
node --test tests/api.test.cjs tests/http.test.cjs tests/structure.test.cjs
node tests/browser-flow.cjs --file
node tests/browser-flow.cjs --api
node tests/design-audit.cjs --after
```
