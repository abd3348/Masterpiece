## الأعطال المؤكدة حسب الأولوية

### 1. مرتفع: طلب قديم يكمل حتى بعد إزالة الأدمن للإعلان

**إعادة الإنتاج:** أنشئ طلبًا على إعلان منشور؛ الأدمن يفحص الإعلان ويحذفه؛ المالك يوافق على الطلب القديم؛ المستأجر يوقّع ويكمل الفحص وتأكيد الاتفاق. جميع الخطوات نجحت وأُنشئ إيجار نشط على الإعلان المحذوف.

**السبب:** `backend/Services/Rentals.cs:24` و`:45` يفحصان حالة الطلب وتوفر التواريخ دون إعادة التحقق من حالة نشر العقار. `Available` يفحص المدة والتداخل فقط.

**الإجراء المقترح:** منع الموافقة الجديدة وتوقيع/تفعيل الطلبات غير المكتملة عندما يصبح الإعلان deleted/pending/archived، مع الإبقاء على سجل العقود التي كانت نشطة قبل الإزالة. لا يلزم إلغاء إيجار قائم تلقائيًا.

### 2. مرتفع: رفع فيديو تقرير الحالة من الصفحة لا يُحفظ

**إعادة الإنتاج:** افتح تقرير استلام لإيجار نشط، اختر MP4 صحيحًا، أكّد الفحص واضغط Save. تظهر الرسالة `Existing media must include its server id.` ولا يُرسل الملف إلى `/api/media`.

**السبب:** `js/shared/condition.js:60` يبني `{name,url}` دون `file`، بينما `js/remote.js:31` يحتاج `file` لرفع الملف الجديد. صفحة إضافة العقار تمرّر `file` بشكل صحيح.

**الأثر:** يمنع إنشاء التقارير من الواجهة، وبالتالي يعطّل إغلاق الإيجار الذي يشترط التقريرين.

**الإجراء المقترح:** الاحتفاظ بكائن File وتمريره لطبقة الرفع، وإضافة اختبار متصفح فعلي يحفظ التقرير ثم يعيد تحميله.

### 3. متوسط: طلب الإيجار الجزئي يختفي عن صاحبه إذا لم يكن لديه إيجار رئيسي

**إعادة الإنتاج:** مستأجر عنده طلب غرفة مقبول، ولا يملك إيجارًا رئيسيًا. البيانات تعيد طلبه فعلًا، لكن صفحة Partial rentals تعرض فقط «استأجر أولًا» ولا تعرض الطلب المقبول أو نموذج ترتيب اللقاء.

**السبب:** `js/tenant/sublets.js:6` و`:9` يرجعان مبكرًا عند غياب الإيجارات ويخفيان قسم Requests and meetings أيضًا.

**الإجراء المقترح:** فصل صلاحية إنشاء عرض غرفة عن مشاهدة الطلبات الواردة/الصادرة وترتيب اللقاءات؛ إخفاء نموذج الإنشاء وحده عندما لا تتوفر أهلية النشر.

### 4. متوسط: تقرير صالح عبر API قد يعطّل صفحة الحالة

**إعادة الإنتاج:** الـAPI يقبل تقريرًا بعنصر واحد اسمه Walls، كما تفعل اختبارات التكامل. عند فتح هذا التقرير من الواجهة تظهر `Cannot read properties of undefined (reading 'condition')` وتفشل الصفحة.

**السبب:** `js/shared/condition.js:38` يفترض ستة عناصر مرتبة ويقرأ `saved?.items[i].condition`، والـBackend يقبل من عنصر إلى 30 عنصرًا.

**الإجراء المقترح:** توحيد عقد عناصر التقرير أو مطابقتها بالاسم مع معالجة العنصر الغائب؛ الحفاظ على نفس أسماء عناصر التقريرين للمقارنة.

### 5. منخفض: حسابك يظهر ضمن زملاء السكن المقترحين

بعد حفظ تفضيلات مشاركة السكن، bootstrap يعيد ملف المستخدم نفسه ضمن roommates. `js/tenant/roommates.js:23` يعرضه مع أزرار الاختيار واللقاء. `chooseRoommate` والـBackend يمنعان اختيار النفس لاحقًا؛ المشكلة زر غير قابل للاستخدام وتجربة مربكة، وليست تجاوز صلاحيات.

**الإجراء المقترح:** استبعاد `p.userId === currentUser.id` عند عرض المرشحين.

## سلوك يحتاج قرارًا أو تحسينًا

- تعليق حساب المالك يُبطل دخوله، لكن رابط تفاصيل إعلانه المنشور بقي متاحًا للضيف أثناء التعليق. لم يظهر الإعلان في الكتالوج في السيناريو لأن لديه إيجارًا نشطًا أصلًا؛ لذلك لم أثبت ظهوره بالبحث بسبب التعليق. إن كان التعليق يعني إيقاف النشاط العام أيضًا، فيلزم فحص Active عند عرض العقارات وبدء طلب جديد.
- يمكن تأكيد استلام مفاتيح إيجار يبدأ السنة القادمة. هذا ممكن بالكود ومستخدم في الاختبارات. يلزم تحديد إن كان مسموحًا لتسجيل تسليم مبكر أو يجب تقييده بتاريخ الاستلام.
- `js/api.js:121` يحسب `null <= commute` كتوافق صحيح في JavaScript. الإعلانات الجديدة لا يملأ نموذجها قيمة Commute؛ لذلك لا يصح عرض «مدة المواصلات مناسبة» بثقة عند غياب المعلومة. المكان ووقت الانتقال لا يُحسبان بخدمة خرائط.
- صفحة السوق تستخدم أرقام trend ثابتة وأشهر May–Oct. إحصاء الباحثين من `state.users` يصبح صفرًا للضيف والمستخدم العادي لأن قائمة المستخدمين لا تُرسل إلا للأدمن. الصفحة موسومة توضيحية، لكنها لا تمثل إحصاءات عامة فعلية.
- بعض نصوص الاتفاق والتقارير ما زالت تقول sample/preview أو «الفيديو محلي» في وضع API أيضًا، رغم أن الحسابات والتقارير محفوظة على السيرفر. يجب مواءمة النص مع وضع التشغيل، دون الادعاء بوجود توقيع قانوني أو تحليل فيديو آلي.
- bootstrap يجمع بيانات كثيرة ويجري استعلامات متتابعة لكل عقار/طلب/إيجار. لم يُجرَ اختبار حمل؛ هذه نقطة قابلية توسع تحتاج قياسًا قبل زيادة البيانات، وليست مشكلة أداء مثبتة بهذا التدقيق.

## ما لم يُثبت كخدمة إنتاجية

- الدفع الحقيقي غير مربوط؛ صفحة Development محاكاة صريحة، وProduction يرفض التحصيل حتى إعداد مزود دفع.
- Forgot password يعرض معلومات فقط؛ تغيير كلمة المرور مع معرفة الحالية يعمل، لكن إرسال رابط استرداد بالبريد غير منفذ.
- المساعد والفحص قواعد ثابتة؛ لا توجد خدمة AI لتحليل الصور أو الفيديو.
- اختُبرت الدعوة والموافقة ونافذة الانضمام للقاءات عبر API؛ لم تُجر مكالمة Jitsi فعلية بين جهازين بكاميرا وميكروفون.
- صور العرض والخطوط وبعض خدمات الفيديو تحتاج الإنترنت. تدقيق التصميم حجب المصادر الخارجية ليفحص التعامل مع غيابها؛ لا يثبت توافر تلك الخدمات.
- لم يشمل التدقيق اختبار حمل أو اختراق شامل أو تحققًا مستقلًا من النسخ الاحتياطية واستعادة SQL.
